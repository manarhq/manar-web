# Dependency decisions

Populated as dependencies were actually added during Phase 1 implementation,
per the Phase 1 Foundation design spec (`docs/superpowers/specs/2026-08-18-phase1-foundation-design.md`
in `manar-api`), Section G. Not written retroactively.

## Toolchain: npm -> pnpm

The repo started as a stock `create-next-app` output using `package-lock.json`.
The Phase 1 design spec's CI section (F) specifies pnpm for both `manar-api`
and `manar-web`, and the sibling `manar-api` repo (NestJS) also uses pnpm, so
`manar-web` was migrated to keep lockfile discipline consistent across the
TypeScript repos rather than maintaining two different package managers for
no functional reason.

- **Selected version**: pnpm 11.20.0 (pinned via the `packageManager` field
  in `package.json` and `Dockerfile`'s `PNPM_VERSION` build arg).
- **License**: MIT.
- **Docs consulted**: https://pnpm.io/installation, https://pnpm.io/continuous-integration,
  https://pnpm.io/next/settings.
- **Installation method**: `pnpm import` (converts `package-lock.json` to
  `pnpm-lock.yaml` without re-resolving versions), then `package-lock.json`
  removed and `node_modules` reinstalled with `pnpm install`.
- **Why selected**: matches `manar-api`; fast, content-addressable store;
  strict-by-default dependency resolution catches phantom dependencies
  early.
- **Alternatives considered**: staying on npm (rejected - the whole point
  was cross-repo consistency); yarn (not otherwise in use in this project).
- **Follow-up config**: `pnpm-workspace.yaml` sets `nodeLinker: hoisted`.
  pnpm's default symlinked/isolated `node_modules` layout produced an
  incomplete Next.js `output: standalone` trace for `@swc/helpers` (only
  the statically-detected `cjs` files were copied into `.next/standalone`,
  not the `esm` export subpath Next's runtime require-hook resolves),
  which crashed the Docker runtime image with `MODULE_NOT_FOUND`. Hoisted
  (flat) `node_modules` matches the layout Next's output file tracing is
  primarily tested against and resolved it; verified with a full
  `docker build` + `docker run` + `curl /api/health` cycle.
